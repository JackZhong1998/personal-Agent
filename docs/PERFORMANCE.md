# 对话等待排查

本版保持按需生成，不预生成后续台词，不调用大语言模型或语音识别。

已减少的等待：

- 英文台词和中文翻译随对话返回，打开中文不再需要额外请求。推荐回复的中文也为预写内容。
- 一次录音提交内，录音保存与下一句角色语音准备并行执行；两项都结束后才释放会话锁，成功后才推进并结算。失败重试复用已有音频，不重复发放积分。
- Supabase 播放直接读取存储对象，不再先查询一次音频元数据；私有录音仍在接口入口校验所属用户。
- 同一轮推荐读音成功后，客户端重听直接复用音频地址；音频继续在主应用持久缓存。
- 录音发送立即显示本地录音，回复等待显示秒数。点击录音会暂停播放，不必等整条语音结束。
- 删除旧样式、重复装饰和自定义字体请求。奖励只使用轻量的位移与透明度动画。

## 查看耗时

在浏览器 Network 中查看响应的 `Server-Timing`，不包含对话正文、用户标识或密钥：

| 接口 | 指标 |
| --- | --- |
| `/api/conversation/turn` | `session`：上传解析、锁与会话读取；`quota`：调用额度；`audio_prepare`：并行录音保存及角色音频缓存/生成；`persist`：会话与积分落库。 |
| `/api/audio` | `audio_storage`：存储读取耗时。 |

各阶段不包含最终网络传输和释放最外层会话锁的耗时，不能视作用户端总耗时。首次未缓存的 Cartesia 语音仍需等待真实生成；Render 免费实例冷启动仅影响推荐回复读音。端到端测试使用模拟语音，验证交互和缓存，不代表线上供应商延迟。

若仍卡顿，先根据接口与阶段定位，再检查 Vercel、Supabase 的实际区域及供应商响应；不要仅凭一次慢请求判断是用户网络问题。
